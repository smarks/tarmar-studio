{% comment %} The contents of the Campaign tab (issue #579), inside its
in gm/_panel_campaign.html. gm-panel-characters.js swaps this in from gm:campaign_panel while a turn runs, alongside the Characters tab, so the section itself -- and whether it is shown -- stays put. Everything here is read from the records the plan actions write, the same rows the model is handed in its state block, so the pane and the GM cannot disagree about where the party is or what state a thing is in. That was the whole complaint: an iron box that was resting on a ledge, then chained, then fused to the rock, with nothing in between that changed it. A Game Master may also set these records by hand (issues #789, #790): add, correct, retire, resolve or remove. The controls are rendered for his account only (can_edit_records) and the endpoints check the account again; a player reads the same lists without them. gm-records.js posts the forms. Each record the Game Master set himself says so (hand_mark), and each row carries its number, which is how the model and the Game Master name it to each other. {% endcomment %}
